Bug Hunter Installation & Usage Guide (v2.0)
============================================

QUICK START (No Installation Required!)
---------------------------------------

Bug Hunter is pure Python with NO external dependencies (no pip packages).
Just download and run:

  1. Navigate to the Bug-Hunter folder:
     cd Bug-Hunter

  2. Run the smooth auto flow:
     python3 bug_hunter.py --auto

  3. It reads your WiFi context, sweeps the LAN for routers, and audits
     the best candidate — all with live probes against the real unit.

  (The classic single-target flow still works: python3 bug_hunter.py)


PLATFORM-SPECIFIC INSTRUCTIONS
-------------------------------

### Windows
  - Install Python 3.8+ from python.org
  - Open Command Prompt or PowerShell
  - Run: python bug_hunter.py

### Linux / Raspberry Pi
  - Python 3 is usually pre-installed
  - Run: python3 bug_hunter.py

### macOS
  - Install Python from python.org or use Homebrew: brew install python
  - Run: python3 bug_hunter.py

### Termux (Android)
  - Install Termux from F-Droid or Play Store
  - Install Python: pkg install python
  - Navigate to the folder: cd /path/to/Router-Os/Bug-Hunter
  - Run: python bug_hunter.py

### FreeBSD
  - Install Python: pkg install python3
  - Run: python3 bug_hunter.py


USAGE EXAMPLES
--------------

  SMOOTH AUTO FLOW (recommended — finds the router for you):
  # WiFi context + LAN sweep + audit the best router candidate
  python3 bug_hunter.py --auto

  # List every router/ONT on the LAN, then audit each (max 6)
  python3 bug_hunter.py --discover --audit --max-targets 6

  PHYSICAL HUNT (audit the real router on your LAN):
  # Auto-detect your gateway and audit the live unit
  python3 bug_hunter.py

  # Physical audit of a specific unit: saves the hunt to audits/ and
  # diffs later runs against the previous ones (drift tracking)
  python3 bug_hunter.py 192.168.10.1 --audit

  # ...with the sticker identity of the physical unit (e.g. a PTCL DSL-226):
  python3 bug_hunter.py 192.168.10.1 --audit \
      --model DSL-226 --firmware PT_1.10_J2 --hw J2 \
      --serial <serial on sticker> --mac <mac on sticker>

  The sticker values are cross-checked against what the unit reports
  about itself; contradictions are flagged as MISMATCH in the report.

  CREDENTIALED DEEP AUDIT (your own router, your own password):
  # Password is prompted (hidden) when you pass -u without -p
  python3 bug_hunter.py 192.168.1.1 -u admin --audit

  # ...plus read-only shell audit and config-backup download
  python3 bug_hunter.py 192.168.1.1 -u admin --shell auto --dump-config --audit

  # Well-known-default check only (slow, explicit, stops at first hit)
  python3 bug_hunter.py 192.168.1.1 --check-defaults

  LOW-LEVEL MTD DUMP (over the credentialed shell; confirms first):
  python3 bug_hunter.py 192.168.1.1 -u admin --shell telnet --dump-mtd all --yes

  OFFLINE FIRMWARE ANALYSIS (local file, nothing uploaded):
  python3 bug_hunter.py --analyze-firmware audits/mtd_192.168.1.1_mtd5_*.bin

  # Scan a specific IP address without saving
  python3 bug_hunter.py 192.168.1.1

  # Save a detailed text report
  python3 bug_hunter.py --report my_scan.txt

  # Save a JSON report (for automation)
  python3 bug_hunter.py --json my_scan.json

  # Quick scan (faster, fewer checks)
  python3 bug_hunter.py --quick

  # Enable deep probes (UPnP, rom-0, SNMP/DNS UDP)
  python3 bug_hunter.py --probe-upnp --probe-rom0 --probe-udp

  # Force vendor detection (18 vendors supported)
  python3 bug_hunter.py --vendor mikrotik

  # Verbose output (see all HTTP requests)
  python3 bug_hunter.py -v

  # See all options
  python3 bug_hunter.py --help


DEMO MODE (play only — does NOT touch your router)
--------------------------------------------------

See Bug Hunter in action with a simulated vulnerable router:

  python3 demo_scan.py

This starts a mock D-Link router on localhost and shows how the tool detects
vulnerabilities and generates reports. To audit the REAL device on your
network, always use bug_hunter.py directly (see PHYSICAL HUNT above).


TESTING
-------

Run the test suite to verify everything works:

  python3 test_scanner.py

All tests should pass with ✓ marks.


WHAT THE TOOL CHECKS
--------------------

✓ Auto-detects your router/gateway
✓ Fingerprints vendor (D-Link, ZTE, TP-Link, Huawei, Netgear, etc.)
✓ Scans for open ports (HTTP, SSH, Telnet, FTP, SNMP, UPnP, etc.)
✓ Checks vendor-specific vulnerabilities:
  - D-Link: webproc auth bypass, Wi-Fi key leak, file traversal
  - ZTE: UPnP WLAN disclosure, CSRF, info leaks
  - TP-Link: rom-0 config exposure, command injection, etc.
✓ Runs generic security checks (all routers)
✓ Generates detailed reports with:
  - CVE references and source URLs
  - Severity ratings (CRITICAL, HIGH, MEDIUM, LOW, INFO)
  - Detailed descriptions and impact analysis
  - Step-by-step fix/remediation methods


SAFETY
------

✓ READ-ONLY BY DEFAULT: Unauthenticated phases use GET/HEAD only (plus one
  SNMP GET / DNS TXT with the explicit --probe-udp). No config changes, ever
✓ CREDENTIALED PHASES ONLY READ: -u/--check-defaults/--shell/--dump-* use
  passwords YOU supply, LAN-only, to enumerate and dump to local 0600 files.
  No brute force beyond the short default list, no cracking, no escalation
  without credentials
✓ LAN-ONLY: Refuses to scan public IPs
✓ NO SECRETS: Never prints passwords or Wi-Fi keys — shell transcripts and
  firmware findings are redacted ([REDACTED])
✓ NO EXPLOITS: Does not run exploit code or payloads — the dnscfg.cgi
  probe (CVE-2026-0625) is a bare reachability GET with no injection
  parameters, same class as every other check
✓ AUDIT DATA STAYS LOCAL: audits/ is git-ignored, device reports are never
  committed to the repository
✓ NO INSTALLATION: Pure Python, standard library only (optional: system ssh)


TROUBLESHOOTING
---------------

Problem: "Could not auto-detect gateway"
Solution: Specify the router IP manually:
          python3 bug_hunter.py 192.168.1.1

Problem: "does not resolve to a private/LAN address"
Solution: Make sure you're scanning a device on YOUR network.
          The tool only scans private IPs (192.168.x.x, 10.x.x.x, etc.)

Problem: "Connection refused" or timeout
Solution: The router's HTTP port might be different. Try:
          python3 bug_hunter.py 192.168.1.1 --port 8080

Problem: No vulnerabilities found
Solution: Exit code 0 means the checks that ran did not match a known
          issue. It is not a guarantee. An INFO finding such as
          "bypass not demonstrated" means the probe was rejected, not
          that the bug is absent. Read the model note: a Boa banner is
          not an ACME/D-Link inference. Keep firmware updated anyway.


REPORT FORMAT
-------------

Text Report (.txt):
  - Human-readable format
  - Detailed descriptions with ASCII boxes
  - Easy to read and share
  - Includes all CVE links and fix steps

JSON Report (.json):
  - Machine-readable format
  - For automation and integration
  - Can be parsed by scripts
  - Same data as text report


EXIT CODES
----------

  0 = No findings from the checks that ran (not a guarantee the unit is clean)
  1 = Minor findings (LOW/INFO severity)
  2 = High-severity findings
  3 = Critical-severity findings
  130 = Interrupted by user (Ctrl+C)

Use exit codes in scripts:
  python3 bug_hunter.py 192.168.1.1
  if [ $? -eq 3 ]; then
    echo "CRITICAL vulnerabilities found!"
    # Take action...
  fi
